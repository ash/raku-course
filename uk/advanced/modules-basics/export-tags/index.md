Позначення підпрограми як `is export` кладе її до _типової_ групи експорту модуля — тих імен, які приносить звичайний `use`. Надавши `is export` _мітку_, ви можете розсортувати експорти по іменованих групах і дозволити кожній програмі обрати потрібний їй набір.

Мітку записують у дужках після `is export`:

```raku
unit module Greeting;

sub hello($name)   is export            { "Hello, $name!" }
sub goodbye($name) is export(:partings) { "Goodbye, $name!" }
```

`hello` не має мітки, тож належить до типової групи; `goodbye` позначено міткою `:partings`.

Звичайний `use` імпортує лише типову групу:

```raku
use Greeting;      # hello доступна; goodbye ні
```

Називання мітки імпортує натомість ту групу — і, можливо, несподівано, _не_ типову на додачу:

```raku
use Greeting :partings; # goodbye доступна; hello ні
```

Запит `:partings` дає вам саме цю групу. Щоб підтягнути все, що експортує модуль, скористайтеся вбудованою міткою `:ALL`:

```raku
use Greeting :ALL; # і hello, і goodbye
```

Дві особливі мітки варто знати. `:ALL` підтримується кожним модулем і імпортує всі його експорти. `:MANDATORY` — та, яку можна поставити на підпрограму, що має імпортуватися незалежно від того, яку мітку обрав викликач.

Кожна мітка насправді є пакунком усередині пакунка `EXPORT` модуля — наприклад, `Greeting::EXPORT::partings`, — і саме це перелічує [інтроспекція модулів](/uk/advanced/module-introspection). Мітки дозволяють більшому модулю тримати свою типову поверхню невеликою, водночас пропонуючи додаткові можливості на запит.
