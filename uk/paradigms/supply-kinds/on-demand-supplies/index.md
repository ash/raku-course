Потік _на вимогу_ виробляє свої значення заново для кожного підключення. `Supply.from-list` є потоком на вимогу: кожне підключення отримує **всю** послідовність від початку, незалежно від будь-якого іншого підключення.

```raku
my $s = Supply.from-list(1, 2, 3);

my @a;
my @b;
$s.tap(-> $v { @a.push($v) });
$s.tap(-> $v { @b.push($v) });

say @a; # [1 2 3]
say @b; # [1 2 3]
```

Обидва підключення отримали всі три значення. Потік не «витратив» своїх значень на першому підключенні; він просто виконався ще раз для другого. Саме така поведінка потрібна, коли потік представляє фіксоване джерело — список, файл, запит, — яке кожен підписник має побачити повністю.

На вимогу — це типова поведінка для потоків, побудованих із наявних даних, бо кожен споживач природно очікує повної послідовності. Інший різновид, _живий_ потік, поводиться зовсім інакше, як показує наступна тема.
