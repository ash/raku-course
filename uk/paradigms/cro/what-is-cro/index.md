Cro — це набір бібліотек для побудови **сервісів**, тобто програм, що спілкуються з іншими програмами через мережу. Найбільше він відомий завдяки HTTP, але вміє й WebSockets, і будує все на реактивних засобах із попередніх розділів цієї частини: [потоках значень](/uk/paradigms/supplies), `react` та `whenever`. Обробник запиту в Cro є, по суті, реакцією на потік вхідних запитів. Його домівка з повною документацією та прикладами — [cro.services](https://cro.services).

Що Cro дає вам понад сирі сокети:

* **Маршрутизація** — відображення шляхів URL на код, що їх обробляє, замість розбору запитів вручну.
* **Об'єкти запиту та відповіді** — читання параметрів запиту й надсилання JSON без збирання тексту.
* **Конкурентність** — багато клієнтів обслуговуються водночас, у пулі потоків, автоматично.
* **Компонованість** — сервіси будують із невеликих частин, які можна тестувати й поєднувати.

Встановлюють його з екосистеми:

```
zef install cro
```

Cro — великий фреймворк із багатьма залежностями, тож це забирає кілька хвилин. Якщо встановлення спиниться на ідентичності залежності, якої воно не може знайти, — з помилкою, що згадує щось на кшталт `JSON::Fast:ver<0.19+>:auth<cpan:TIMOTIMO>`, — ваш примірник `zef` застарий, щоб знати архів, який обслуговує такі історичні ідентичності модулів. Оновіть сам встановлювач через `zef install zef`, відкрийте свіжий термінал і запустіть встановлення Cro знову.

Cro зводить увесь курс докупи: об'єктноорієнтоване проєктування для його типів, функційний стиль у його обробниках і реактивну модель для його потоків запитів. Наступна тема показує найменший можливий сервіс на Cro, щоб ви побачили, як ці ідеї сходяться в справжньому вебкоді.
