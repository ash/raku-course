В разделе «Основы» вы познакомились с [_мульти-функциями_](/ru/essentials/more-on-functions/multi-functions): несколькими подпрограммами с одним именем, где Raku выбирает нужную, анализируя типы аргументов. Этот механизм называется _множественная диспетчеризация_.

До сих пор выбор определялся _типом_ аргументов. Конструкция `where` позволяет пойти дальше и выполнять диспетчеризацию также по _значению_. Она записывается после параметра и содержит условие, которому должен удовлетворять аргумент, чтобы был выбран данный кандидат:

```raku
multi sub info(Int $n where $n < 0)  { say "$n is negative" }
multi sub info(Int $n where $n == 0) { say "$n is zero" }
multi sub info(Int $n where $n > 0)  { say "$n is positive" }

info(-5);
info(0);
info(7);
```

Каждый вызов направляется к тому кандидату, чьё условие истинно для данного значения:

```
-5 is negative
0 is zero
7 is positive
```

Все три кандидата имеют одинаковую сигнатуру с точки зрения типов — один `Int` — и без конструкций `where` они бы конфликтовали. Условия делают их различными.

## Базовый случай для рекурсии

Частое применение `where` — определение точки остановки рекурсии в виде отдельного кандидата. Вот факториал, разделённый на два мульти-подпрограммы:

```raku
multi sub fact(Int $n where $n <= 1) { 1 }
multi sub fact(Int $n)               { $n * fact($n - 1) }

say fact(5); # 120
```

Первый кандидат обрабатывает базовый случай (`$n` равно `1` или меньше) и просто возвращает `1`. Все остальные значения попадают во второй кандидат, который вызывает `fact` снова с меньшим числом. Внутри функции нет никакого `if` — выбор между базовым случаем и рекурсивным шагом делается диспетчером.
